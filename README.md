# CS-230-Operating-Platforms
CS 230 portfolio featuring The Gaming Room software design document and operating platform analysis.
Project Overview
For this project, I worked with The Gaming Room, a client who wanted to expand its Android game, Draw It or Lose It, to other operating platforms. The goal was to design a web-based application that could support multiple teams and players while keeping game information organized and consistent.
1. Client and Software Requirements
The Gaming Room wanted to expand Draw It or Lose It beyond Android devices. The application needed to support multiple teams, allow multiple players on each team, keep game and team names unique, and make sure only one instance of the GameService class existed in memory at a time. The design also needed to consider which operating platform would best support the application.
2. What I Did Well
I think I did well at organizing the requirements and comparing different operating platforms to determine which would work best for the client. I also included important details about the application's structure, design patterns, memory, storage, and security. This helped me understand how to plan an application before moving into development.
3. What I Found Helpful About the Design Process
Working through the design document helped me break the project into smaller sections and understand what needed to be done before writing code. Creating the UML diagram and identifying how the classes would work together made the application easier to understand. Having that plan in place can save time and help prevent mistakes during development.
4. What I Would Revise
If I could revise one part of my document, I would add more detail to the operating platform comparison and explain the advantages and disadvantages of each option more clearly. I would also make sure every recommendation directly connects to the client's requirements. This would make it easier for the client and development team to understand why certain decisions were made.
5. Understanding and Meeting User Needs
I focused on the client's goal of expanding the game so users could access it from different operating platforms. I considered how games, teams, and players would be organized and how the application could maintain unique names and consistent information. Understanding user needs is important because the final software should solve the client's problem and provide a reliable experience. Without understanding those needs, developers could spend time building features that do not meet the user's expectations.
6. My Approach to Software Design
My approach was to review the requirements, compare operating platforms, identify design constraints, and use object-oriented principles and design patterns to organize the application. In future projects, I would continue using requirements analysis, UML diagrams, platform comparisons, and testing plans before coding. I would also review the design as the project progresses so I can catch problems early and make improvements before they become more difficult to fix.
